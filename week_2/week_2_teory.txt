2.1 Базовые конструкции Python
Определения ключевых понятий

Условный оператор if / elif / else — конструкция, которая позволяет выполнять разные блоки кода в зависимости от истинности условия.
Простыми словами: «Если условие выполняется — делай одно, иначе — делай другое».

match-case (структурное сопоставление, Python 3.10+) — современная и более читаемая альтернатива длинным цепочкам if-elif-else. Работает как «switch», но мощнее.

Цикл while — цикл с предусловием. Выполняется, пока условие истинно. Используется, когда заранее неизвестно точное количество итераций.

Цикл for — цикл по коллекции (списку, диапазону, строке). Самый часто используемый цикл в автотестах.

range() — функция, которая генерирует последовательность чисел. Часто используется с for.

Список (list) — упорядоченная изменяемая коллекция элементов.

List comprehension — компактный способ создания нового списка на основе существующего в одну строку.

Оператор break — немедленно прерывает выполнение цикла.

«Магические» числа и строки — жёстко прописанные в коде значения (например, if status == 200 или sleep(5)). Такие значения непонятны без контекста, их сложно менять. Правило курса: никаких магических значений — только именованные константы и переменные.

Примеры кода + подробный разбор
Пример 1. Функция «День недели» (рекомендуется match-case)

def get_day_name(day: int) -> str:
    match day:
        case 1:
            return "Понедельник"
        case 2:
            return "Вторник"
        case 3:
            return "Среда"
        case 4:
            return "Четверг"
        case 5:
            return "Пятница"
        case 6:
            return "Суббота"
        case 7:
            return "Воскресенье"
        case _:
            return "Неверный день недели"
Подробный разбор:
match day: — сравниваем значение переменной.
Каждый case X: — отдельная ветка. Код читается как «если день равен 1 — вернуть Понедельник».
case _: — срабатывает для всех остальных значений (аналог else).
Преимущество перед if-elif: код чище, легче добавлять новые условия, меньше вероятность ошибки.

Пример 2. Поиск максимума без встроенных функций + break

numbers = list(range(1, 8))          # [1, 2, 3, 4, 5, 6, 7]
max_value = numbers[0]               # берём первое число как начальное

for n in numbers:
    if n > max_value:
        max_value = n
    if n == 5:                       # демонстрация break
        break

print(f"Максимум: {max_value}")
Подробный разбор:
list(range(1, 8)) — создаём список от 1 до 7.
max_value = numbers[0] — избегаем магического числа, берём первое значение списка.
Цикл for n in numbers: — проходим по каждому элементу.
if n > max_value: — классическая логика поиска максимума.
if n == 5: break — прерываем цикл досрочно.

Пример 3. List comprehension (фильтрация)

words = [f"str{i}" for i in range(10)]
print(words)                         # ['str0', 'str1', ..., 'str9']

long_words = [word for word in words if len(word) > 5]
print(long_words)
Подробный разбор:
[f"str{i}" for i in range(10)] — создаём список в одну строку.
if len(word) > 5 — условие фильтрации.
List comprehension почти всегда быстрее обычного цикла и гораздо читаемее.

Дополнительно

Условные конструкции и match-case
match-case появился в Python 3.10 и быстро стал стандартом. Он особенно удобен при обработке HTTP-статусов, кодов ошибок и различных состояний в тестах. В отличие от длинных if-elif, он делает код визуально чище и снижает вероятность ошибок при добавлении новых условий.

Циклы while и for
while используется, когда количество итераций заранее неизвестно (ожидание появления элемента, polling). for — когда мы проходим по уже известной коллекции (список результатов тестов, набор тестовых данных). Комбинация for + range() — самый частый паттерн в автотестах.

List comprehension
Это не просто «синтаксический сахар». В реальных проектах автотестов вы будете постоянно фильтровать, трансформировать и создавать списки тестовых данных, результатов запросов и отчётов. List comprehension делает такой код короче и быстрее.

Магические числа и строки
Правило, которое вводится уже на этой неделе и действует до конца курса: если число или строка появляется в коде больше одного раза или её смысл не очевиден из контекста — выносите в константу или переменную с понятным именем. Это одно из базовых правил чистого кода в профессиональной разработке тестов.

2.2 ООП: классы, объекты, наследование и ссылочные типы
Определения ключевых понятий

Класс — это шаблон (чертёж), по которому создаются объекты.
Простыми словами: класс — это как рецепт торта. Сам по себе он ничего не делает, но по нему можно испечь много одинаковых тортов.

Экземпляр класса (объект) — это конкретный «выпеченный» объект, созданный по шаблону класса. У каждого объекта есть своё состояние (данные).

__init__ (конструктор) — специальный метод, который автоматически вызывается при создании объекта. Он нужен, чтобы сразу задать начальные значения атрибутов.

Ссылочный тип (изменяемый объект) — когда вы передаёте объект в функцию или фикстуру, передаётся не копия, а ссылка на него. Поэтому любое изменение внутри функции видно снаружи.
Важно: в Python изменяемые типы — list, dict, set, пользовательские классы. Неизменяемые — int, str, tuple, bool.

Наследование — механизм, при котором один класс (дочерний) может получить все методы и атрибуты другого класса (родительского).

Инкапсуляция — принцип, по которому внутреннее устройство объекта скрыто от внешнего кода. В Python реализуется через соглашения _protected и __mangled.
STAR-объяснение
Situation
В реальном проекте автотестов вы будете создавать десятки классов: Page Objects, модели тестовых данных, хелперы. Без понимания, как работает __init__ и почему объекты — ссылочные, вы будете тратить часы на отладку странных багов в фикстурах и тестах.

Action
Практика строится на трёх ключевых примерах: класс Car, класс Lead + функция change_name (демонстрация ссылочного типа), класс Student + расчёт среднего балла + фильтрация через list comprehension.

Result
Вы получаете уверенное понимание, как организовывать код автотестов через классы, и избегаете типичных ошибок с изменяемым состоянием объектов в фикстурах.
Примеры кода + подробный разбор
Пример 1. Простой класс (будущий Page Object)

class Car:
    def __init__(self, brand: str, model: str, year: int):
        self.brand = brand
        self.model = model
        self.year = year

    def print_car_info(self) -> None:
        print(f"{self.brand} {self.model} ({self.year})")


car1 = Car("Toyota", "Camry", 2022)
car2 = Car("BMW", "X5", 2023)
car3 = Car("Lada", "Vesta", 2021)

car1.print_car_info()
car2.print_car_info()
car3.print_car_info()
Подробный разбор:
class Car: — объявление класса.
def __init__(self, brand, model, year): — конструктор. self — ссылка на текущий объект.
self.brand = brand — сохраняем переданные значения как атрибуты объекта.
car1 = Car(...) — создание экземпляра (объекта). При этом автоматически вызывается __init__.

Пример 2. Ссылочный тип (самый важный для понимания фикстур)

class Lead:
    def __init__(self, name: str):
        self.name = name


def change_name(lead: Lead, new_name: str) -> None:
    lead.name = new_name          # меняем атрибут объекта


lead = Lead("Иван")
print(lead.name)                  # Иван

change_name(lead, "Пётр")
print(lead.name)                  # Пётр  ← изменение видно снаружи функции!
Подробный разбор:
При передаче объекта lead в функцию передаётся не копия, а ссылка.
Поэтому lead.name = "Пётр" внутри функции меняет оригинальный объект.
Это поведение критично понимать при работе с pytest-фикстурами.

Пример 3. Класс + list comprehension (фильтрация тестовых данных)

class Student:
    def __init__(self, name: str, age: int, grades: list[float]):
        self.name = name
        self.age = age
        self.grades = grades

    def get_avg_grade(self) -> float:
        if not self.grades:
            return 0.0
        return sum(self.grades) / len(self.grades)


students = [
    Student("Анна", 20, [4.5, 5.0, 4.8]),
    Student("Борис", 21, [3.2, 4.0, 3.8]),
    Student("Вера", 19, [4.9, 5.0, 4.7]),
]

good_students = [s for s in students if s.get_avg_grade() > 4.1]

for student in good_students:
    print(f"{student.name}: {student.get_avg_grade():.2f}")
Подробный разбор:
Класс Student хранит данные о студенте.
Метод get_avg_grade защищён от пустого списка.
List comprehension фильтрует объекты по условию — очень частая операция в автотестах.

Важно запомнить
Класс — это шаблон. Объект — это конкретный экземпляр с данными.
__init__ вызывается автоматически при создании объекта через ClassName(...).
В Python почти все пользовательские классы — ссылочные типы. Это главная причина «странного» поведения фикстур в pytest.
List comprehension — не просто «красивый синтаксис», а инструмент, который вы будете использовать каждый день при работе с результатами тестов и тестовыми данными.

Почему ООП важно именно в AQA
Page Object Model — это по сути набор классов. Каждый экран или крупный компонент инкапсулируется в свой класс. Фикстуры pytest часто возвращают объекты. Без глубокого понимания ссылочных типов ты будешь регулярно сталкиваться с флакинг-тестами(нестабильные\падающие) из-за того, что состояние объекта неожиданно изменилось между тестами.

Примеры кода + подробный разбор (имитация нагрузки)
import random
import time

LOAD_THRESHOLD = 85          # именованная константа вместо магического числа
ITERATIONS = 10
SLEEP_SECONDS = 0.2

def simulate_load_monitoring() -> None:
    """Имитация мониторинга нагрузки Rostics."""
    iteration = 0
    while iteration < ITERATIONS:
        load = random.randint(0, 100)
        print(f"Итерация {iteration + 1}: нагрузка {load}%")

        if load > LOAD_THRESHOLD:
            print("⚠️  ВНИМАНИЕ: Высокая нагрузка!")

        time.sleep(SLEEP_SECONDS)
        iteration += 1

if __name__ == "__main__":
    simulate_load_monitoring()
Подробный разбор:

2.4 Code Quality 101
Определения ключевых понятий

Форматирование кода — приведение кода к единому стилю (отступы, пробелы, переносы строк). Делает код читаемым для всей команды.

Линтинг — автоматическая проверка кода на ошибки стиля, потенциальные баги и нарушения соглашений.

black — самый популярный автоформаттер для Python. Применяет единый стиль, не спорит о пробелах.

flake8 — статический линтер. Находит ошибки стиля и потенциальные проблемы.

isort — инструмент для сортировки импортов по стандарту PEP 8 (опционально на этом этапе).

pre-commit — инструмент, который автоматически запускает проверки (black, flake8 и др.) перед каждым коммитом (будет настроен позже).
STAR-объяснение
Situation
В современных командах автотестирования код тестов рассматривается как полноценный production-код. Споры о форматировании и стиле отнимают время и снижают скорость разработки.

Task
Выработать привычку использовать black и flake8 перед каждым коммитом. Это базовый уровень культуры качества кода.

Action
Установить инструменты, прогнать их на коде недели, исправить замечания, добавить в requirements.txt.

Result
Код становится единообразным, команда тратит меньше времени на обсуждение стиля, а вырабатывается полезная профессиональная привычка.
Примеры + подробный разбор
До black:

def   get_day_name ( day:int)->str :
    if day==1:return "Понедельник"
    elif day==2 : return "Вторник"
После black:

def get_day_name(day: int) -> str:
    if day == 1:
        return "Понедельник"
    elif day == 2:
        return "Вторник"
Подробный разбор:
black автоматически выравнивает отступы, пробелы вокруг операторов и приводит код к единому стилю.
Вы больше не тратите время на споры «сколько пробелов» или «куда поставить скобку».
flake8 дополнительно подсвечивает слишком длинные строки, неиспользуемые переменные и другие проблемы.

Инструменты добавлены в requirements.txt.
Любой Pull Request с этой недели содержит только код, прошедший black + flake8.
Важно запомнить
На данном этапе не требуется идеальная настройка pre-commit hooks.
Главная задача — выработать привычку прогонять black и flake8 перед созданием коммита.

Почему качество кода важно уже сейчас
В 2025–2026 годах в большинстве зрелых команд black — это абсолютный стандарт форматирования. Он полностью убирает споры о стиле кода в команде. flake8 помогает находить потенциальные проблемы и «пахучий» код ещё до того, как тест упал. Привычка прогонять эти инструменты перед каждым коммитом — это базовая профессиональная дисциплина, которую лучше всего формировать уже на ранних этапах обучения.

Вопросы к собеседованию — по теме недели
Разбираем устно с ментором или письменно своими словами. Отмечаем неуверенные ответы.

Что такое класс и экземпляр класса? — Класс — шаблон, экземпляр — конкретный объект, созданный по этому шаблону. Каждый объект хранит своё состояние.
Что такое __init__ и для чего он используется? — Конструктор. Вызывается автоматически при создании объекта, инициализирует атрибуты.
В чём разница между изменяемыми и неизменяемыми типами данных? Приведите примеры. — list, dict, set — mutable; tuple, str, int — immutable. Изменяемые типы передаются по ссылке.
Что такое ссылочный тип и как это проявляется при передаче объектов в функции? — Передаётся не копия, а ссылка. Изменение видно снаружи функции (пример с Lead).
Что такое list comprehension и когда его целесообразно использовать? — Компактный способ создать список: [x*2 for x in range(5) if x > 1]. Используется для фильтрации и трансформации данных.
Зачем нужны инструменты black и flake8 в тестовом проекте? — Единый стиль форматирования и автоматическая проверка качества. Команда тратит меньше времени на обсуждение стиля и быстрее находит проблемы.
